# 战斗节点（Combat Nodes）

> 状态：已实现 schema 10 + 新面板。  
> 目标位置：时间轴弹窗 → 原「团战」Tab。

## 0. 实现状态

- 回放导出器 schema 10 增加 `combat.events`、伤害来源、伤害分类与 1 秒 `combat.samples`；
- 新面板 `CombatNodePanel.vue` 已接入时间轴；
- 旧 schema 缓存会自动失效并重新解析；
- 当前节点算法集中在 `ui/src/lib/combatNodes.ts`。


## 1. 产品定义

「团战」Tab 改为「战斗节点」。

节点不再只统计 6 人以上团战，而是以**所选分析对象**为中心，收集与其击杀、助攻、阵亡有关的所有战斗。

一个节点可以是：

- 单杀；
- 2v2 / 3v3 小规模接战；
- 4v5 / 5v5 团战；
- 连续击杀、买活后继续打；
- 分析对象助攻但未击杀的抓人。

节点必须能回答：

- 这一波谁参与了？
- 分析对象做了什么？
- 谁对分析对象造成了伤害？
- 双方交出了哪些技能、物品和普攻？
- 资源、HP、MP、阵亡发生了什么变化？
- 这一波是谁赢了，为什么？

## 2. 节点锚点

每个节点由**英雄死亡事件**作为锚点。

如果一次英雄死亡满足以下任一条件，则成为分析对象的候选锚点：

```text
focus 是击杀者（killer）
focus 是阵亡者（victim）
focus 是助攻者（assist）
```

其中助攻来自回放死亡事件的 `assist_players`，不使用“造成过伤害”代替。

### 节点合并

两个锚点满足以下条件时合并为同一个节点：

```text
时间差 ≤ 12 秒
且
两个锚点至少有一个共同参战英雄，或击杀位置距离 ≤ 2500
```

默认参数：

```text
MERGE_WINDOW = 12s
MERGE_DISTANCE = 2500
```

连续团战、买活后继续打、追杀到第二个击杀，会归入同一节点。  
两条发生在不同区域、没有人员重叠的击杀不会因为时间接近而被硬合并。

### 节点时间窗

```text
start = 第一个锚点 - 8 秒
end   = 最后一个锚点 + 8 秒
```

再根据窗口内实际战斗事件向前/向后微调，但不早于比赛开始。

## 3. 节点类型

按参战英雄数和死亡数分类：

| 类型 | 条件 |
| --- | --- |
| 单杀 | 2 名英雄，1 次死亡，无助攻 |
| 小规模 | 3–5 名英雄 |
| 团战 | ≥6 名英雄 |
| 多杀节点 | 分析对象在节点内击杀 ≥2 |
| 助攻节点 | 分析对象只有助攻、没有击杀/阵亡 |

类型只是展示标签，不影响节点统计。

## 4. 参战判定

节点窗口内满足任一条件的英雄进入「参战英雄」：

- 造成英雄伤害；
- 承受英雄伤害；
- 释放技能；
- 使用物品；
- 获得击杀或助攻；
- 在节点内阵亡；
- 分析对象本人。

只有位置、没有任何战斗行为的英雄不进入参战表，可单独标记为「在附近但未参战」。

## 5. 每个节点的数据

### 5.1 基础信息

```text
id
start / end / duration
type（单杀 / 小规模 / 团战 / 多杀 / 助攻）
focusRole（击杀 / 助攻 / 阵亡 / 多杀 / 参与）
result（天辉胜 / 夜魇胜 / 均势）
participantCount
```

### 5.2 分析对象摘要

```text
英雄 / 玩家 / 阵营
击杀 / 助攻 / 阵亡
造成伤害（物理 / 魔法 / 纯粹）
承受伤害（物理 / 魔法 / 纯粹）
HP 开始 / 最低 / 结束
MP 开始 / 最低 / 结束
金钱变化
经验变化
等级变化
释放技能（时间、技能、目标、次数）
使用物品
普攻次数 / 普攻伤害
```

### 5.3 参战英雄

每个英雄一行：

```text
英雄、玩家、阵营
击杀 / 助攻 / 阵亡
造成伤害：物理 / 魔法 / 纯粹
承受伤害：物理 / 魔法 / 纯粹
治疗 / 护盾
HP 开始 → 结束，最低 HP
MP 开始 → 结束，最低 MP
金钱变化
经验变化
等级变化
技能释放列表
物品使用列表
普攻次数 / 普攻伤害
```

### 伤害来源修正

- 无 `inflictor` 的物理伤害才可能标记为普通攻击；
- 无 `inflictor` 的魔法/纯粹伤害如果 2.5 秒内同一施法者对同一目标有明确技能/物品伤害，继承该来源（例如血腥榴弹 DoT 的最后一跳）；
- 裂魂人的 Greater Bash 等被动伤害使用明确来源标签，不再误标普通攻击；
- `item_madstone_bundle` 等中立道具管理事件不进入战斗节点；
- Invoker 的 `quas / wex / exort / invoke` 组件不进入技能列表，只保留实际释放的 invoked 技能。

### 时间精度

战斗时间线显示 `MM:SS.mmm`，底层回放事件精度为 0.1 秒。

### 5.4 谁伤害了分析对象

按“施法者 + 伤害来源 + 伤害类型”聚合：

```text
施法者英雄
来源：普攻 / 技能名 / 物品名
类型：物理 / 魔法 / 纯粹
命中次数
总伤害
占比
```

同时保留事件级明细，供时间线展开：

```text
时间、施法者、来源、类型、伤害、目标 HP 剩余
```

### 5.5 战斗事件时间线

节点内按时间排序：

```text
技能释放
物品使用
普攻命中
英雄受伤
治疗/护盾
英雄阵亡
买活
```

事件必须能关联到英雄；不展示小兵、野怪、建筑伤害。

### 5.6 资源变化

用节点开始、结束和最低点展示：

```text
HP / MP：开始、最低、结束
金钱：开始、结束、差值
经验：开始、结束、差值
等级：开始、结束
```

HP/MP 来自回放采样，建议 1 秒一个点；金钱/经验来自玩家资源采样。

## 6. 数据来源与缺口

### 现有数据

当前回放已经提供：

- 5 秒级 HP/MP、金钱、经验、等级、KDA；
- 5 秒级位置与 HP；
- 分析对象击杀、阵亡、技能、物品事件；
- 全局伤害/承伤汇总；
- OpenDota 的团战切分与聚合。

### 不足

现有 `ReplayParse` 没有：

- 所有英雄的逐次技能释放时间线；
- 所有英雄的普攻/技能伤害事件；
- 伤害类型（物理/魔法/纯粹）；
- 每次死亡事件的助攻玩家；
- 节点级的 HP/MP 高频变化；
- 分析对象逐次承伤的来源列表。

因此，**只靠 OpenDota `teamfights` 无法完成这个功能**。

### 回放层可提供的数据

Clarity 的 `CombatLogEntry` 已提供：

```text
getDamageType()
getHealth()
getAbilityLevel()
getAssistPlayers()
getAttackerTeam() / getTargetTeam()
getLocationX() / getLocationY()
getNetworth()
getGoldReason() / getXpReason()
```

可新增 schema 10：

```text
combat: {
  events: [
    [t, kind, attacker, target, inflictor, value,
     damageType, healthAfter, attackerTeam, targetTeam, assistSlots]
  ],
  samples: [
    [t, slot, hpPct, mpPct, gold, xp, level]
  ]
}
```

事件类型：

```text
DAMAGE
ABILITY
ITEM
HEAL
DEATH
```

仅保留英雄相关事件，过滤小兵、野怪、建筑和无关单位。

### 数据量

- 1 秒采样：40 分钟 × 10 人 ≈ 24,000 个采样点；
- 英雄技能/物品事件：通常几千条；
- 英雄对英雄伤害事件：通常 1–3 万条；
- 节点只在前端生成，原始事件按需保留。

需要在服务器端缓存解析结果，避免每次打开时间轴重复解析。

## 8. 统计口径

- 不使用官方“团战”定义；节点是基于回放事件的启发式切分；
- 12 秒合并窗口和 8 秒前后窗口是产品参数，会写入说明；
- 伤害只统计英雄对英雄；
- 普攻与技能的分类：
  - 有 `inflictor` 的技能伤害归入技能；
  - 无 `inflictor` 的英雄攻击归入普攻；
- 金钱、经验、HP、MP 是采样值，允许少量误差；
- 节点结果按双方击杀差判定，击杀相同看经济差。

## 9. 验收标准

- 分析对象的每一次击杀、阵亡、助攻都能在某个节点中找到；
- 单杀节点不会被 6 人门槛过滤；
- 连续 12 秒内的相关击杀合并为一个节点；
- 不同区域、无人员重叠的击杀不被错误合并；
- 参战英雄的技能、普攻、伤害类型、HP/MP、金钱、经验、阵亡均有数据或明确空态；
- “谁伤害了分析对象”能追溯到施法者、技能/普攻、伤害类型；
- 旧缓存不崩溃，提示重新解析；
- 大型节点渲染不阻塞时间轴交互。
