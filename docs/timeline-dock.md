# 复盘时间轴弹窗（Timeline Modal）设计

> 目标版本：TrueSight 本地复盘应用
> 关联：`ui/src/App.vue`（分析区）、`MatchCard.vue`（对位选择）、`ResultCard.vue`（分析正文）
> 数据基础：`data/names/*.json`（英雄/技能/天赋/装备中英名）+ OpenDota / STRATZ / 回放解析

## 1. 设计目标

通过分析页右下角的「时间轴」按钮打开一个**大尺寸弹窗**，把「分析对象 + 对位角色」的比赛过程做成可拖动预览的数据驾驶舱：

- 一条时间滑条驱动全部数据：出装、技能加点、天赋、补刀、财产、经验、KDA；
- 同一屏内完成「分析对象 vs 对位」的横向对比；
- 读正文时随时展开核对，不打断阅读；
- 数据缺失时明确降级，不编造。

**非目标**：不做录像播放器；不做逐帧战斗回放；不在本期内做多场比赛对比。

## 1.1 显示条件与触发时机

- 时间轴只属于**高级分析**：必须已有回放解析结果（`replayData`）且已选择分析对象；
- 普通分析、回放仍在解析、回放解析失败时不显示时间轴入口；
- 回放解析完成后入口出现；弹窗默认关闭，点击打开；
- 入口按钮只在弹窗关闭时显示；弹窗不会自动弹出；
- 对位玩家的走势用回放 5 秒采样；背包只显示分析对象的 6+1+3 格。

## 2. 典型使用场景

1. 读完「对线期」段落后，拖到 6:00 看双方补刀差和第一件装备时间；
2. 看到「12 分钟被单杀」时，点时间轴上的击杀标记，确认当时双方装备与等级；
3. 对位分析里比较「谁先做出关键装」，用两条出装轨对齐时间；
4. 复盘加点：确认 10 级天赋与 27 级补选是否合理。

## 3. 入口与弹窗布局

### 3.1 入口按钮

- 有出装或加点数据时，分析页右下角出现胶囊按钮「时间轴」（`clock` 图标）；
- 点击打开弹窗；弹窗关闭后按钮重新出现；没有数据时不显示入口。

### 3.2 弹窗（尽可能大）

```
┌────────────────────────── 遮罩 ──────────────────────────┐
│ ┌──────────────────────── 弹窗 ────────────────────────┐ │
│ │ 时间轴  露娜·天辉  对位：潮汐/宙斯            ✕     │ │
│ ├──────────────────────────────────────────────────────┤ │
│ │ 时间滑条                                             │ │
│ │ 此刻指标（4 磁贴）                                   │ │
│ │ ┌───────────────────────┬──────────────────────────┐ │ │
│ │ │ 出装路线              │ 同位置结论               │ │ │
│ │ │ 走势                  │ 技能与天赋               │ │ │
│ │ └───────────────────────┴──────────────────────────┘ │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

- 弹窗尺寸 `width: min(1560px, 96vw)`、`height: min(940px, 92vh)`，居中铺开；
- 圆角 22px、深色半透明遮罩 + `backdrop-filter: blur(6px)`，层级 `z-index: 60`；
- 打开时锁定页面滚动（`body.overflow = hidden`），关闭后恢复；
- 关闭方式：右上角 ✕、`Esc`、点击遮罩空白处。

### 3.3 内部布局（按弹窗宽度自适应）

- 头部：标题 + 分析对象 + 对位头像组 + 关闭；
- 主体用容器查询（`container-type: inline-size`）：
  - 默认单列：出装 → 走势 → 结论 → 技能天赋；
  - `≥860px`（弹窗实际宽度基本都会命中）：两列，左列「出装路线 + 走势」（1.65fr），
    右列「同位置结论 + 技能与天赋」（1fr），四个区块各自成卡片；
  - 走势图在宽布局下加高到 200px，出装轨获得接近 900px 的时间宽度。

### 3.4 小屏

- `<900px`：弹窗占 `98vw × 94vh`，指标磁贴变 2×2，头部允许换行。

## 4. 弹窗结构（自上而下）

### 4.1 头部

- 左侧：`时间轴` 标题；
- 中间：分析对象头像 + 中文名 + 位置（如「露娜 · 天辉」）；
- 右侧：对位成员头像组（最多 3 个，点击切换下方技能天赋的展示对象）、关闭按钮。

### 4.2 时间控件

- 播放/暂停；倍速 1× / 2× / 4×；
- 滑条：0 → 比赛时长（秒），刻度每 5 分钟；游标显示 `mm:ss`；
- 事件吸附开关：靠近击杀 / 装备 / 天赋节点时轻微吸附；
- 键盘：`←/→` ±1 分钟（`Shift` ±5 分钟）、`Home/End` 首尾、空格播放。

### 4.3 「此刻」指标（四个磁贴）

| 磁贴 | 主值 | 副值（对位差） |
|---|---|---|
| 净值 | `networth_t[t]` | `+820` 绿色 / `-430` 红色 |
| 补刀 | `lh_t[t]` / `dn_t[t]` | 与对手补刀差 |
| 经验 | `xp_t[t]`（+ 估算等级） | 等级差 / 经验差 |
| KDA | `k / d`（实时）+ 最终助攻 | —— |

> 助攻没有时间线，只有终局总数：显示为 `k / d / (a 终局)` 并在 tooltip 说明。

### 4.4 出装轨

- 分析对象一行：横向时间轴，显示**所有购买**——消耗品、真假眼、榴弹、诡计之雾、显隐之尘、图纸、合成前散件；
- 合成品显示为「小件 → 成品」：小件 12px，成品 24px 金色边框；普通购买 18px；
- 同一时间点的多个购买纵向堆叠；同种物品 10 秒内合并，图标右下角显示数量；
- 悬停：自绘浮窗，显示物品名 + 时间 + 价格 + 去向（已卖出/已使用/已升级为福佑/已交给熊/已合成）；守卫会标注「假眼/真眼」；
- 守卫组合按成品时间向前找最近的侦查/岗哨守卫配对，避免用 0:00 的出门眼；
- 点击：游标跳到该时间；
- 行尾：高级分析显示回放 6 装备 + 1 打野装备 + 3 背包的「此刻背包」；装备栏/打野/背包分组显示；
- 合成关系可用细线连接（配件 → 成品），默认关闭，开关在标题栏。

### 4.5 技能与天赋

- 技能卡：每个技能显示 Dota 2 技能图标（CDN `dota_react/abilities`），右下角叠加当前等级徽章；
  图标加载失败时用技能名首字兜底；终极技能用金色边框重点标注，先天技能带「先天」标签；
- 加点序列：按实际加点顺序排列，每个点显示技能图标 + 等级数字叠加；天赋显示 `T{层}`，
  属性附加显示 `+`；未到时间的点置灰，终极技能的点同样金色边框；
- 天赋梯：4 层 × 2 节点，10/15/20/25 与 27/28/29/30 两轮；已选高亮，未选置灰；
- 属性附加（`special_bonus_attributes`）：显示已点次数 / 7；
- 技能/天赋顺序来自 OpenDota（回放没有可靠的逐次升级时间），时间按回放等级估算。

### 4.6 对比曲线

- 主图：净值折线（2–4 条），当前时间竖线游标；回放模式使用 5 秒采样，最多 730 个点；
- 切换：补刀 / 经验 / 英雄伤害；
- KDA 磁贴显示当前时刻 K/D/A（回放助攻来自实体流，不再是终局值）；KDA 与英雄伤害使用 PlayerResource 官方结算，包含德鲁伊小熊、狼、佣兽等召唤物；
- 图例即角色头像，点击可隐藏某条线。

### 4.7 脚注

- 数据来源徽标：`回放` / `OpenDota` / `STRATZ`；
- 时间口径：已转换为对局时间（已扣开局偏移）；
- 缺失提示：如「本场未解析，仅 STRATZ 5 分钟采样」。

## 5. 交互规格

- 单一状态源：`cursorSec`（秒），所有区块从它派生，避免各组件各自维护时间；
- 拖动滑条用 `requestAnimationFrame` 合并更新，60fps 下不重排；
- 播放：`setInterval` 100ms 步进，按倍速换算；
- 关闭再打开不重置时间与选中对象；
- 历史记录里的高级分析条目带「时间轴」按钮：先恢复该场分析对象，再读取该英雄的回放解析并直接打开本面板；粗略分析或解析失败时不打开；
- 正文联动（P2）：Markdown 里的 `[12:34]` 渲染成可点击 chip，点击把游标移到 12:34，
  并高亮对应事件；反之拖动滑条不滚动正文，避免干扰阅读。

## 6. 数据契约

### 6.1 每人时间线（逐分钟）

```ts
interface PlayerTimeline {
  slot: number
  heroId: number
  isRadiant: boolean
  isFocus: boolean
  points: Array<{
    minute: number
    netWorth: number | null   // networth_t
    lastHits: number | null   // lh_t
    denies: number | null     // dn_t
    xp: number | null         // xp_t
    level: number | null      // 由 xp 推算，标记 estimated
    kills: number             // kills_log 累计
    deaths: number            // deaths_log 累计
    assists: number | null    // 仅终局
  }>
  purchases: Array<{ sec: number; key: string; source: 'replay' | 'opendota' }>
  upgrades: Array<{ order: number; ability: string; tier?: number }>
  talents: Array<{ key: string; tier: number; picked: boolean }>
  attributePicks: number
  finalItems: string[]
}
```

### 6.2 字段来源与缺口

| 数据 | 来源 | 粒度 | 缺口处理 |
|---|---|---|---|
| 净值 | 回放 `series.netWorth`（5 秒）> OpenDota `networth_t`（分钟） | 5 秒 / 分钟 | 回放优先 |
| 补刀/反补 | 回放 `series.lastHits/denies`（5 秒）> `lh_t` / `dn_t` | 5 秒 / 分钟 | 回放优先 |
| 经验 | 回放 `series.xp`（5 秒）> `xp_t` | 5 秒 / 分钟 | 回放优先 |
| 等级 | 回放 `series.level`（5 秒）> `xp_t` + 经验表 | 5 秒 / 分钟 | 回放优先 |
| K/D/A | 回放 `series.kills/deaths/assists`（5 秒）> `kills_log` / `deaths_log` | 5 秒 / 事件 | 回放优先，助攻不再是终局值 |
| 装备 | 回放 `purchases` + `sells` + `items`（6 装备 + 1 打野 + 3 背包） | 事件/快照 | 回放优先；时间轴只在回放可用时显示 |
| 技能顺序 | `ability_upgrades_arr` | 顺序 | 无时间戳，见下 |
| 天赋 | 同上 + 层级表 | 顺序 | 同上 |
| 属性附加 | `special_bonus_attributes` 次数 | 次数 | 无 |

### 6.3 技能加点的时间定位（关键取舍）

`ability_upgrades_arr` **只有顺序、没有时间**，且数组长度可能小于等级（部分属性附加未被记录）。
因此：

- 技能条默认只展示**顺序**，不假装精确时间；
- 需要上时间轴时，用「锚点 + 插值」：天赋层固定锚在 10/15/20/25（第二轮 27–30），
  其余加点在相邻锚点之间按顺序均分，整体标 `估算`；
- 根治方案（P3）：给 `java/MatchJsonMain.java` 增加技能等级事件输出，拿到真实学习时间。

### 6.4 时间口径

- 一律用**对局时间**；回放购买时间已由导出器扣除 `clockOffsetSec`；
- 负时间（赛前购买）归到 0 秒并标「赛前」；
- 比赛时长以 `match.duration` 为准，滑条上限留 5 秒余量。

## 7. 视觉规范

- 复用 `styles/tokens.css`：`--panel`、`--line`、`--text-dim`、`--accent`；
- 天辉/夜魇用现有绿/红语义色，对手线用虚线；
- 字号：标题 13px/600，数值 18px/650，辅助 11px；
- 图表线宽 1.6px，游标 1px 虚线，数据点 3px；
- 动效遵循 `prefers-reduced-motion`，此时弹窗动画瞬时完成。

## 8. 状态矩阵

| 场景 | 表现 |
|---|---|
| 比赛已解析（OpenDota 有数组） | 全部区块可用 |
| 未解析 / 数组为空 | 只显示装备购买与击杀事件，指标区提示「本场未解析」 |
| 仅 STRATZ | 净值 5 分钟采样、死亡事件；无装备/技能，显示降级说明 |
| 仅回放 | 装备与击杀精确；无逐分钟经济，曲线隐藏 |
| 无对位选择 | 只显示分析对象，头部提示「可在上方选择对位」 |
| Turbo / 时长异常 | 滑条按实际时长，刻度自适应 |

## 9. 技术实现

### 9.1 组件拆分

```
App.vue
└─ TimelineDock.vue            # 入口按钮、弹窗、遮罩、Esc/滚动锁定
   ├─ DockHeader.vue           # 标题/头像/对位/关闭
   ├─ TimelineScrubber.vue     # 滑条 + 播放 + 键盘
   ├─ MetricTiles.vue          # 四个磁贴 + 差值
   ├─ ItemTrack.vue            # 每人一行出装轨
   ├─ LoadoutStrip.vue         # 当前装备/终局装备
   ├─ SkillTrack.vue           # 技能等级点 + 顺序号
   ├─ TalentLadder.vue         # 4 层天赋 + 二轮
   └─ CompareChart.vue         # SVG 折线 + 游标
```

### 9.2 数据流

```
match/stratz/replay + roster + matchup
        │
        ▼
lib/timeline.ts  buildTimelineModel()   // 纯函数、可单测、按比赛缓存
        │
        ▼
TimelineModel { durationSec, players: PlayerTimeline[] }
        │
        ▼
TimelineDock(cursorSec) → 各区块只读派生
```

- `buildTimelineModel` 复用现有 `heroes`、`roster`、`matchup` 数据；
- 名称查询走 `data/names/*.json`（英雄/技能/天赋/装备中英名），避免硬编码；
- 结果 `Map<matchId, TimelineModel>` 缓存，避免重复计算。

### 9.3 性能

- 逐分钟数组只在首帧解析一次，滑条更新只做索引读取（O(1)）；
- 折线用 SVG `path` 预生成，游标单独 transform；
- 弹窗关闭时停止播放与图表重绘；
- 图标懒加载，失败回退英雄/装备占位图。

## 10. 分期计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 入口按钮 + 弹窗骨架 + 滑条 + 四磁贴 + 出装列表 + 技能顺序条 | 能打开、能对照 |
| P1 | 出装轨、对比曲线、事件标记、点击跳转、键盘 | 交互完整 |
| P2 | 等级推算、天赋梯、正文时间戳联动、回放精确购买 | 数据闭环 |
| P3 | 回放导出器输出技能学习事件，去掉「估算」 | 时间精确 |

## 11. 验收标准

1. 弹窗打开/关闭动画 ≤ 300ms，`Esc` 与遮罩点击都能关闭；
2. 滑条任意位置，四个磁贴与图线在 1 帧内更新；
3. 弹窗覆盖正文但不引起布局位移，关闭后页面滚动位置不变；
4. 未解析比赛不出现编造数值，明确显示降级原因；
5. 键盘可完成「移动游标 / 播放 / 关闭弹窗」；
6. 切换比赛后数据正确重算，缓存不串场。

## 12. 已确认的产品决策

1. 对位角色最多 **3 个**（边路通常 2 个，中路 1 个，极少数 3 人一路）；分析对象固定在最前。
2. **结论卡按“双方同位置”出**（我方 1 号位 vs 对方 1 号位），默认展示分析对象所在位置，
   可切换 1–5 号位；没有位置数据时降级为“对位结论”。
3. 时间滑条带播放（1×/2×/4×）、事件标记、点击跳转。

## 13. 设计取舍说明

- **弹窗而不是常驻浮层**：分析正文是长文，常驻浮层会一直遮挡；弹窗按需打开、
  尺寸足够大，核对完即关闭，阅读与查看互不打断。
- **单一 `cursorSec` 驱动全部区块**：避免“出装停在 12 分、曲线停在 20 分”的错位。
- **逐分钟而非逐秒**：OpenDota 的经济/补刀/经验数组本身就是每分钟一个点；
  强行插值会制造假精度，滑条以秒为单位只是为了让游标连续。
- **技能加点不假装精确时间**：数据只有顺序；先按天赋锚点插值并标注「估算」，
  后续用回放事件替换。
- **助攻不上时间轴**：只有终局总数，硬拆会误导。
- **数据来源徽标常驻**：同一张图里可能混用回放与 OpenDota，必须让用户知道当前值来自哪。

## 14. 实施状态（P0 + P1 已完成）

已落地：

- 入口按钮 + 大弹窗：`min(1560px, 96vw) × min(940px, 92vh)`，遮罩 + 滚动锁定，
  Esc/遮罩/右上角关闭，窄屏自适应；
- 时间滑条：播放/倍速、键盘（←/→、Shift、Home/End、空格）、天赋层与关键装标记；
- 四磁贴：净值 / 补刀 / 经验+等级 / KDA（助攻标注终局），带对位差值；
- 同位置结论卡：1–5 号位切换，10 分钟、20 分钟、首件 2000+ 装备、终局 KDA；
- 出装轨：每人一行，图标按时间定位，悬停看名称/时间/价格，点击跳转；赛前购买单独计数；
- 技能与天赋：按等级估算已学加点、等级点、加点顺序号、8 条天赋的已选/已解锁状态、属性附加次数；
- 走势图：净值/补刀/经验/英雄伤害切换，点击图表跳转；
- 数据层：`/api/names` 读中英名表；`lib/timeline.ts` 纯函数建模；`lib/names.ts` 名称索引。

浅色适配：

- 弹窗内部颜色全部改成组件级 CSS 变量（`--dock-bg` / `--dock-soft` / `--dock-track` 等），
  默认深色，`light` 类下切换为浅色；
- 浅色类由 `config.mode` 驱动（而不是 `:global()` 选择器——`vue-tsc`/Vite 编译后
  `:global(:root[data-mode=light]) .dock` 会丢掉 `.dock`，变量落到 `:root` 上不生效）；
- 图标点、轴标、天赋/属性标签都有独立变量，避免浅色下“看不见”；
- 回归：`DOCK_URL=...mode=light... node tools/names/dock_ui_test.mjs` 会校验弹窗底色为白、
  深色模式仍为深绿，入口按钮/弹窗尺寸/滑条/节点数/关闭逻辑照常通过。
